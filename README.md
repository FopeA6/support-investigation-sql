# Support Investigation SQL

A small, **synthetic** database and five investigation cases, written to practise the work of a support engineer: use SQL and logs to find out whether a customer problem is **configuration, data, documentation or a real product defect**, then hand it on with clear evidence.

All data is generated by `seed.py`. It is not real customer data.

## Run it
```bash
python seed.py                              # builds support.db (Python 3, standard library only)
python run.py sql/02_orders_not_shipped.sql # run one investigation
python -m unittest tests/test_cases.py      # 5 tests, one per case
```

## The five cases
| # | Symptom | Finding | Type |
|---|---|---|---|
| 1 | Charged twice | Same payment event recorded twice (6 orders) | Product defect (idempotency) |
| 2 | US orders never shipped | No US entry in the warehouse map (56 orders) | Configuration |
| 3 | Totals don't add up | 37 cent difference on discounted orders (4 orders) | Product defect (rounding) |
| 4 | Parcels for missing orders | Shipments left after orders deleted (3) | Data integrity |
| 5 | Report counts differ | UTC vs UTC+1 day boundary (10 orders) | Expected behaviour / docs |

Each case has a write-up in `cases/` in the format an escalation should have: classification, impact, repro steps, evidence, root-cause hypothesis, and what to hand to Engineering.
